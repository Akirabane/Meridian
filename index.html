Meridian is a working proxy: it routes players, balances load and moves them between servers without a loading screen, and it held 1,000 typical bot players on one PC with 0 players lost. An optimisation that cuts the processor use by about 2.5 times has been merged (pull request #160).

  • Tested with real game servers and real clients over a real network (3 players), and with up to 1,500 bots.
  • Not measured yet: the game server's own speed (TPS) with many players. See "Not tested yet".

Meridian is a proxy for Horizon, a Rust version of Minecraft Java Edition. Players connect to the proxy, and it sends each of them to one of several servers behind it, and can move a player to another server without a loading screen.

With the Horizon team

Meridian is developed in the open, as a project separate from Horizon. The Horizon team, the maintainers of Horizon, gave directions on how to go about it, and they decide what goes into Horizon itself. Their requests are on a public issue of Horizon: small pull requests, one at a time. These directions are not an endorsement of Meridian.

See Horizon issue #7484.

The machines

The test PC

  • Windows 11
  • Intel i9-14900KF: 8 fast cores (2 threads each) + 16 efficiency cores
  • 64 GB of memory
  • The proxy was given 8 threads (4 fast cores); the bots used the other cores

The VPS

  • A KVM virtual machine, Linux (Ubuntu 26.04 LTS, kernel 7.0)
  • 4 virtual cores (1 thread each), shown as Intel Core Processor (Haswell) at 3.0 GHz; the exact model is hidden by the host
  • 8 GB of memory (7.6 GiB usable), no swap
  • 75 GB disk, NVMe according to the provider's offer (the virtual disk does not say)
  • Network: up to about 3 Gbit/s according to the provider's offer; not measured
  • Cores are shared: no sign of contention at rest (0.0 % stolen time), not tested under load

The Internet line

  • 500 Mbit/s down and up (advertised)

Spend less processor time on compression (a second optimisation)

Compression towards the players takes about 41 % of the proxy's processor time with 100 players (one run per setting; the 4 % towards the servers cannot be told from 0). A pool of shared compressors was tried: the measured difference, about 1.7 %, was under the 3 % set before the test, so it is not adopted. A lower compression level is now a setting: at level 4, with 100 players on one real server, the proxy used 11.8 % less processor time for 1.5 % to 1.7 % more bytes. Measured with bots on one machine; level 3 and 500 players are not measured; the default is unchanged, 6.

Not tested yet

This list is part of the results. If something is not shown on this page, it has not been measured.

  • The game server's own speed (TPS) with many players was not measured.
  • More than 3 real players at once: every larger test used bots.
  • The latency at 1,000 typical players: the bots, on the same PC, were the limit.
  • Online mode (encryption): about 1.4 more cores at 1,000 typical players is an estimate, not a measure.
  • Linux above 250 players, and heavy traffic at 1,000 players.
  • 1,000 players connecting in the same second: 114 to 264 logins were lost on this PC (not attributed yet).
